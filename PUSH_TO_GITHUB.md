# Pushing to GitHub — one-time setup

This file is internal — delete it before pushing. It tells you exactly how
to publish the `code/` folder as <https://github.com/pupurayi/lora-credit-scoring>
without leaking anything that shouldn't be public.

## 1. Delete the scaffolding files

From inside `ESWA_FullLength_Package/code/`:

```powershell
# Files that were working notes during the rebuild, not deliverables
Remove-Item -Force SETUP.md
Remove-Item -Force citation_audit.md
Remove-Item -Force PUSH_TO_GITHUB.md     # this file - delete last
```

(`SETUP.md` is superseded by the new public `README.md`; `citation_audit.md`
was an internal record of the bibliography rebuild.)

## 2. Verify nothing sensitive will be committed

```powershell
# From inside code/, dry-run the file list
git init -b main
git add .
git status              # review the list of staged files
```

Expected files to be staged (just the code, configs, and small artefacts):

- `README.md`, `LICENSE`, `.gitignore`
- `requirements.txt`, `requirements-optional.txt`, `setup_env.sh`
- `data/*.py`
- `models/*.py`
- `eval/*.py`
- `figures/generate_figures.py`
- `results/**/*.json`, `results/**/*.csv` (small text files only — predictions and
  parquet are excluded by `.gitignore`)

Expected files **NOT** staged (these would all be excluded by `.gitignore`):

- `data/raw/` — too large (~2.7 GB)
- `data/processed/` — regenerable
- `.venv/` — your virtual environment
- `results/**/*.pt`, `results/**/*_preds.npz` — large binary artefacts
- `figures/*.pdf`, `figures/*.png` — regenerated by the script

If `git status` shows any unexpected files, stop and check `.gitignore`.

## 3. Push

```powershell
git commit -m "Initial public release of reproducibility code"
git remote add origin https://github.com/pupurayi/lora-credit-scoring.git
git push -u origin main
```

GitHub will ask for authentication. Use a Personal Access Token (PAT) from
<https://github.com/settings/tokens>; classic PAT with `repo` scope is fine,
or a fine-grained token scoped to this single repository.

## 4. After pushing — sanity check

Visit <https://github.com/pupurayi/lora-credit-scoring> and confirm:

- The `README.md` renders correctly on the project home page
- The `LICENSE` file is recognised (GitHub will show "MIT" in the right sidebar)
- No `kaggle.json` or other credentials are visible anywhere
- The `data/raw/` and `.venv/` folders are not present

If anything sensitive slipped through, do **not** try to fix it with a
follow-up commit — git history retains everything. Instead:

```powershell
# Wipe the repo and start over (only if the leak is sensitive credentials)
git push --delete origin main
Remove-Item -Recurse -Force .git
# Then redo step 2 carefully
```
